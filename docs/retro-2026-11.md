This retro covers Phase K Wave 13. The dominant themes are
**quarterly automation rhythm** (the JWT rotation rehearsal
moves from operator-triggered to scheduled-quarterly via the
new `jwt-rotation-rehearsal-scheduled.yml` thin scheduler — cron
`0 2 1 */3 *` dispatches the existing W11 inner workflow with
`target_env=staging` forced; the monthly Redis load-test reminder
workflow joins the rhythm with cron `0 14 1 * *` opening a
same-month-idempotent issue with the W12 SLO baseline + 7-day
stale-close), **cluster-policy namespace exclusion closure**
(the W12 retro D7 open item finally lands via a downstream
`PatchTransformer` enumeration approach — eight Kind-specific
strippers run AFTER the NamespaceTransformer; this design was
the second attempt after the empirical reproduction showed the
kustomize v5.4.3 `NamespaceTransformer` `fieldSpecs.kind:` filter
is IGNORED — even with `kind: Deployment` as the only entry, ALL
Kinds still get the namespace stamped), **post-cutover hardening
preparation** (PR-ready `redis-envfrom-required-patch.yaml`
artefact flipping `optional: true → false` for the Redis
connection-string envFrom + `docs/prod-cutover.md §6` "Post-
cutover hardening" narrative covering six W14–W16 tightening
gates with per-gate rollback + per-gate observability mapping),
**regional EKS bring-up readiness docs** (`docs/regional-eks-
bringup.md` NEW — per-region Cutover-Ready checklists for the
four target regions; the doc is the readiness artefact for the
W14+ apply phase once Hicks's regional cluster work reaches
ACTIVE state), and the **Terraform CLI W14 bump survey**
(`docs/terraform.md §6.6` NEW — candidate baselines, seven-
class migration risks table, recommended `1.11.4` provisional
pin, bump-PR shape, rollback path; no actual bump this wave).

The single most important takeaway is **empirical reproduction
beats specification reading**. The W13 ClusterPolicy fix
initially followed the kustomize spec literally —
`fieldSpecs: [{kind: Deployment, ...}]` should restrict the
namespace stamp to just the listed Kinds per the
`NamespaceTransformer` documentation. A minimal repro showed
the `kind:` filter is silently ignored in v5.4.3. The fix
flipped to the inverse design (downstream Kind-by-Kind
strippers running AFTER the stamp) which works as designed.
Lesson: when a kustomize transformer's behaviour doesn't match
the spec, build a 5-resource minimal repro before committing
to a design — the spec is aspirational, the binary is canonical.

## 2. What worked well

* **Cron-scheduler-delegate pattern.** Both new W13 workflows
  (`jwt-rotation-rehearsal-scheduled.yml`,
  `redis-load-test-reminder.yml`) are thin schedulers that
  either dispatch an existing inner workflow or open an
  issue. Zero new operational logic; the W11/W12 inner
  workflows + manual procedures are the source of truth.
  Easy to reason about; easy to back out (delete the
  scheduler, nothing else affected).
* **Kustomize fieldSpecs empirical reproduction.** A
  5-resource minimal repro (`ClusterPolicy` + `Deployment` +
  inline `NamespaceTransformer` with `fieldSpecs: [{kind:
  Deployment, ...}]`) showed within 90 seconds that the
  kustomize v5.4.3 fieldSpecs `kind:` filter is ignored.
  Saved committing to a design that would have failed
  silently in CI (the W12 NamespaceTransformer fieldSpecs
  enumeration was tempting but broken).
* **PR-ready patch artefacts.** The Redis envFrom required-
  flip patch ships as a PR-ready file with full apply
  procedure + rollback + pre-conditions documented in the
  file header, but is NOT wired into `kustomization.yaml`.
  Gives the W14+ owner a fully-baked artefact to apply at
  the right time without re-deriving the patch. Pattern
  worth replicating across the post-cutover hardening
  gates.
* **Per-region readiness checklist template.** The four
  regions in `docs/regional-eks-bringup.md` share the same
  7-gate checklist structure with per-region tweaks
  (eu-west-1 adds GDPR pre-flight; ap-southeast-1 relaxes
  the probe p99 threshold to 200 ms). Adding a 5th region
  in the future is a copy-template + delta exercise.
* **Single-issue-per-month idempotent reminder.** The
  `open-reminder` job matches by title (`Monthly Redis
  load-test reminder — YYYY-MM`); a same-month re-fire
  (e.g. operator manually `workflow_dispatch`'d on day 15
  to ping the team) finds the existing issue and no-ops
  rather than spamming a duplicate. Pattern worth
  replicating for any future monthly reminder workflows.

## 3. What didn't work / open items

* **kustomize fieldSpecs `kind:` filter ignored in v5.4.3.**
  Documented in `docs/cluster-policy-namespace-exclusion.md
  §2.1` with the minimal repro. Upstream issue tracker
  shows the behaviour as a known bug with no fix in the
  v5.x series. The W13 workaround (downstream
  `PatchTransformer` enumeration) is the canonical solution
  until v6. **W14+ hand-off:** if a new cluster-scoped Kind
  is introduced (e.g. by a helm chart upgrade adding a new
  CRD), add a new `PatchTransformer` document at the end of
  `cluster-scoped-fieldspecs.yaml` (the file header has the
  convention). Re-evaluate the whole approach when kustomize
  v6 ships.
* **Per-section-number coordination across docs is fragile.**
  The W13 task spec asked for additions at specific section
  numbers (`redis-cluster.md §5`, `terraform.md §3`) which
  didn't match the actual current section numbering. Placing
  the additions at the semantically-correct sections (§4.6
  and §6.6 respectively) avoided cross-ref breakage but
  diverged from the task spec wording. **Lesson:** when a
  task spec pins a section number, verify the current
  document's numbering BEFORE accepting the pin; flag
  divergences in the W13 history note for downstream
  auditability.
* **Hudson absent in W13 widened DevOps scope unexpectedly.**
  The W12 retro D5 hand-off list tagged the redis-load-test
  reminder workflow as Hudson-lane. With Hudson rolled out
  of W13, DevOps absorbed it. The work itself fits naturally
  in the DevOps lane (it's an ops-cadence workflow), but
  the implicit assumption that lane-tagged hand-offs survive
  agent-absence is something to track. **W14+ hand-off:** if
  a hand-off is tagged for an absent agent, the receiving
  agent should escalate via the decisions inbox before
  absorbing the work, even if the absorption is the right
  outcome.
* **`redis-envfrom-required-patch.yaml` index-pin is fragile.**
  The JSON6902 patch uses array index `4` to target the
  Redis secret envFrom entry. If a future wave re-orders the
  envFrom list (e.g. adds a new secret at index 2), the
  patch will silently target the wrong secret. The file
  header documents the current index mapping, but the patch
  itself can't enforce it. **W14+ hand-off:** before applying
  the patch, verify the built deployment's envFrom list
  matches the header's index mapping via `kustomize build
  infra/k8s/overlays/prod/ | yq '.spec.template.spec.containers[0].envFrom'`.
  Watch upstream kustomize#3625 (path-by-name JSON-Patch)
  and migrate when it ships.

## 4. Lessons learned

* **Empirical reproduction beats specification reading.** The
  ClusterPolicy fix design pivot was driven by a 90-second
  minimal repro that contradicted the kustomize spec.
  Documented as the takeaway up top.
* **Thin scheduler delegates compose better than monolithic
  workflows.** The W11 inner rehearsal workflow stayed
  unchanged when W13 added the scheduler; the W11 inner
  workflow can still be triggered manually for off-cadence
  rehearsals (e.g. post-incident drill). Pattern worth
  applying to other periodic surfaces.
* **`workflow_dispatch` back-stop on every scheduled
  workflow.** Even pure cron-driven workflows should expose
  a `workflow_dispatch` for manual trigger — for catch-up
  if a cron fire fails, for testing post-merge, for off-
  cadence drills. Both W13 workflows include the back-stop.
* **PR-ready-not-wired beats premature apply.** The W13
  Redis envFrom required-flip patch lands as a file in the
  overlay directory but is NOT referenced in
  `kustomization.yaml`. The patch is the design artefact;
  the apply gate is documented separately. Reduces apply-
  too-early risk.
* **Per-Kind stripper enumeration beats opaque filter logic.**
  The W13 fix enumerates eight cluster-scoped Kinds in
  separate `PatchTransformer` docs. Verbose, but each entry
  is obvious in code review (Kind X → strip namespace) and
  adding a new Kind is a 9-line patch.
