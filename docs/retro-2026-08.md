de-duped GitHub issue with the W6 Trivy findings; `prod-health-
check.yml` runs a 5-minute synthetic probe of `/healthz` +
`/readyz` + `/metrics` + `/.well-known/jwks.json` with a
3-strike cooldown for paging).

The single most important takeaway is **§3.1 — the lock-file
cutover discipline**. W9 planned the `/tmp/` → `.work/` cutover
but left the snippet (in §3.7 of the agent-handoff protocol) at
the old path. W10 found this by re-reading the doc as part of
the cutover bring-up: the snippet update is now mandatory in
the cutover plan. The lesson: a "planned" cutover does NOT mean
every reference has flipped — `git grep` for the old path is a
required step in every cutover.

## 3. Lessons learned

### 3.1 A "planned" cutover is not the same as a completed one

W9 documented the `/tmp/squad-git-lock` → `.work/squad-git-lock`
cutover in `docs/agent-handoff-protocol.md` §3.6, but the
companion §3.7 example snippet still read `9>/tmp/squad-git-lock`.
The cutover was "planned" but the docs were inconsistent — a
W10 agent reading §3.7 first would have copied the WRONG path
into a fresh script.

**Fix:** every cutover-plan section MUST include the line `git
grep <old-path>` before the cutover is declared complete. If
the grep returns hits OUTSIDE historical retros (`history.md`,
old `.squad/decisions.md` wave summaries — exempt), the cutover
is not done.

**Carry forward:** updated `docs/agent-handoff-protocol.md`
§3.6 to "**W10 cutover COMPLETE**" with explicit notes that
the EDITED files include §3.7 and that retro `.squad/agents/
*/history.md` files are exempt.

### 3.2 Concurrent-agent collision against `mkdir`

While creating `infra/terraform/modules/redis/`, a concurrent
agent ran `git stash --include-untracked` + `git reset --hard`
in the middle of my edit batch — wiping the freshly-created
module directory. (W9's history.md line 825+ documents the
same collision shape against Apone's untracked work.)

**Fix:** the `mkdir -pv` + placeholder-file pattern recovers
without re-creating the whole structure. After every edit batch
land a backup at `.work/apone-w10-safe/<batch-name>/` so the
recovery cost on the next collision is bounded.

**Carry forward:** the `.work/apone-w10-safe/` backup pattern is
now part of the agent-handoff protocol (informal — codified in
W11+).

### 3.3 CHANGELOG version arithmetic against task prompt typo

The W10 task prompt said "CHANGELOG bump to 0.18.0", but W9
already used 0.18.0 (see `[0.18.0] — Phase K Wave 9`). The
correct bump is 0.19.0 — versions track the wave count, not the
task-prompt number.

**Fix:** the W10 entry is `[0.19.0]`. The prompt typo is
documented in the Phase_K_W10/Apone/ memo so a future audit
can re-confirm.

**Carry forward:** the version-arithmetic check is now part of
the changelog-bump pattern. The wave-decision memo template
(`.squad/decisions/inbox/<agent>-phase-k-wave-N.md`) should
quote the previous wave's version + the new version explicitly.

### 3.4 The prod-health-check 3-strike cooldown design

The synthetic probe could trivially open an issue on the first
5-min cron failure — that's the cheapest possible code path.
But a single failed probe is more often a GitHub Actions
runner regional blip than a prod outage; if the probe pages on
every blip, the on-call ignores the issue label.

**Fix:** 3-strike (~15 min sustained outage) is the floor for
opening an issue. 2-strike clean is the floor for closing it
(prevents a flap-loop). Both thresholds are tunable but the
defaults are tuned for the runner-blip rate observed in W7
during the canary work.

**Carry forward:** the same 3-strike / 2-recovery pattern is
candidate for any future synthetic probe (e.g. a per-region
edge probe in W11+).

### 3.5 JWT rotation cadence — 180d → 90d is a big jump

W9 set 180d. The W10 squad-wide secret-management cadence
review settled on 90d for all secrets (Redis auth-token, OAuth
client secrets, JWT signing keys). Tightening JWT to 90d means
the rotator picks up the task ~2x more often.

**Fix:** the §3 walkthrough is now explicit (`aws ssm
put-parameter` commands inline, JWKS validation inline,
rollback inline). The rotator's cognitive load per rotation is
LOWER even though the cadence is higher.

**Carry forward:** the explicit-walkthrough discipline applies
to any rotation procedure under quarterly cadence. The
secret-management runbook should pick up the same pattern in
W11 for the OAuth + Redis + DB rotations.

## 5. Metric movement

* **Squad git-lock contention.** Pre-W10: `/tmp/squad-git-lock`
  occasionally evicted by an external `/tmp` cleanup, causing
  the lock to be re-created mid-rebase. Post-W10: `.work/`
  lives in the repo tree → zero eviction events expected.
  Will re-baseline in W12.
* **CVE remediation latency.** Pre-W10: open CVE on
  container-scan → manual issue creation by the on-call SRE
  (median 4-6 h). Post-W10: nightly automation → ≤ 24 h
  worst-case to issue, median 0-1 h (the artefact-to-issue
  delta).
* **Prod outage MTTD via synthetic probe.** Net-new metric.
  Floor: 15 min (3-strike cooldown). Ceiling: 0 (Sentry +
  Prometheus alerts fire faster); the probe is a BACKSTOP.
