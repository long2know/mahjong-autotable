effort (CSP enforce + edge WAF tuning + mobile store release
rails + Hudson dashboard reflow). Surveying once + executing
incrementally is materially safer than batching the
remediation into a single mega-wave.

### 1.3 lane-discipline-nightly.yml line-87 heredoc fix (W14 hand-off)

`.github/workflows/lane-discipline-nightly.yml` line 87
heredoc / YAML-block-scalar collision FIXED. The W5-era
unquoted `<<EOF` body started at column 0, breaking out of
the YAML literal block scalar (`actionlint`: "could not parse
as YAML: yaml: line 87"). The W6–W14 baseline carried the
parse error as documented technical debt.

W15 fix is three combined moves: (a) indent the heredoc
body + closing `EOF` to the YAML block scalar base column
(10) so YAML parses cleanly; (b) single-quote the heredoc
tag (`<<'EOF'`) so neither bash expansion nor command
substitution fires inside; (c) pipe scan outputs through
`env:` (`SCAN_ECODE`, `SCAN_OUTPUT`) and substitute via
bash parameter expansion (`${BODY//__DATE__/$DATE}`) after
the heredoc closes.

Verified locally by extracting the rendered bash script via
`yaml.safe_load(...)['jobs']['scan']['steps'][...].['run']`
and exercising the heredoc + substitution path against mock
inputs. Rendered body matches expected shape exactly.

The fix doubles as a portable convention codified at
`docs/agent-handoff-protocol.md §5.10` "Workflow heredoc
convention (W15 — Apone)" — six rules + canonical example
+ audit-trail discipline.

## 2. What worked well

### 2.1 Pre-wire-then-toggle pattern applied to its third gate

The W14 pre-wire pattern (codified for Redis envFrom flip)
extends cleanly to a third Phase K hardening gate (Kyverno
audit → enforce). The pattern's costs are stable across
applications: one wave-N+1 commented-out kustomization edit
+ one new manifest file. The cutover-day uncomment shrinks
from a multi-line block-add diff to a one-line toggle.

The W14 retro identified the pattern's applicability
condition (multi-line behaviour-flip changes). The W15
Kyverno work confirms: enforce-mode flip is a multi-line
behaviour-flip (composing a new ClusterPolicy + ensuring it
doesn't conflict with existing W3/W4 policies), so the
pre-wire pays off. The HPA bump is a single-line value
swap, so it stays single-PR (W15 §1.2 explicitly identifies
the counter-example).

The pattern is now at three applications (Redis envFrom W13
→ W14 wire-up → W15+ uncomment; Kyverno enforce W15 wire-up
→ W16+ uncomment; CSP enforce planned for W16+ wire-up).
Three is canonical; the pattern is stable. Worth promoting
to a top-level discipline (`docs/cutover-discipline.md`?)
post-Phase-K.

### 2.2 Survey-then-execute scales from 2-wave to N-wave

The W14 retro codified the two-wave shape for quarterly
cadence items. W15's SLSA-3 readiness survey extends the
pattern to a THREE-wave sequence (W16+W17+W18). Per-gap
severity scoring + cost estimate + sequencing implication
gives the squad three independent review points instead of
one mega-PR.

The audit trail is the survey output (`docs/slsa-
provenance.md §7b`); each remediation wave's diff is small
+ scoped. Reviewer cognitive cost stays low.

Pattern transferable to ANY multi-wave hardening:
* CSP report-only → enforce (multi-wave because the false-
  positive allowlist needs incremental tuning).
* Hudson dashboard reflow (each panel updated independently;
  survey identifies the dependency graph).
* Mobile store release-rails activation (per-store
  enrolment + per-store credential rotation rehearsal as
  independent waves).

### 2.3 The W5 heredoc bug finally fixed (W6→W14 carry-over CLEARED)

`actionlint .github/workflows/lane-discipline-nightly.yml`
exits 0 for the first time since W5. The fix doubles as a
portable convention (§5.10) so future agents authoring
workflow `run:` blocks won't reproduce the bug.

The six-rule convention is shaped to be self-enforcing:
rule 6 ("verify with actionlint") catches the same bug at
authoring time. Rule 2 ("pipe outputs via env:") prevents
the `${{ }}` / shell interleaving that triggered the
original issue. Rule 4 ("single-quote the heredoc tag")
prevents the bash-expansion / heredoc-body coupling.

The W15 retro lesson: **carry-over technical debt with a
documented fix path is INFINITELY safer than carry-over
debt with no fix path**. The W14 charter explicitly flagged
the heredoc bug as W15+ backlog; the W15 fix landed within
the wave. Compare with cross-lane technical debt (visual
regression spec from W13 Vasquez hand-off) where the fix
path requires Vasquez's lane to land.

### 2.4 Phase L L1 design memo as cross-lane negotiation input

The W14 Phase L pre-plan was the **what** of Phase L. The
W15 L1 design memo is the **how** of Phase L L1
specifically. The 12 DD-numbered decisions are negotiation
hooks: each one names a question, a recommendation, an

The squad's three lanes that consume Phase L deliverables

The pattern is **decision-shaped pre-plan** — surface the
specific questions that need answering, not just the scope.
Worth applying to every future phase pre-plan.

## 4. Lessons learned

### 4.1 Survey-then-execute generalises beyond quarterly cadence

W14 codified the two-wave survey-execute shape for
quarterly items (TF CLI bump, JWT rotation). The W15 SLSA-3
work proves the pattern generalises to ANY multi-wave
hardening where the gap analysis is independent of the
remediation.

The condition: gap analysis can be authored without
executing the remediation. SLSA-3 readiness assessment
doesn't require the remediation to run; it requires the
remediation to be IDENTIFIED. Same for CSP report-only-to-
enforce ramp-up (false-positive allow-list can be drafted
without enabling the policy).

Pattern formalisation: "**survey-N-execute**" — wave N
surveys; waves N+1 through N+M execute the remediation
incrementally; each remediation wave is an independent
review.

### 4.2 Decision-shaped pre-plan beats scope-shaped pre-plan

The W14 Phase L pre-plan was scope-shaped: "here are four
surfaces and approximate wave counts." Useful. The W15
Phase L L1 design memo is decision-shaped: "here are 12
specific design decisions, each with a recommendation,
authority, and blocker."

The decision-shaped memo is materially more useful for
cross-lane negotiation: it gives every other lane a
specific question to answer + a default recommendation
to disagree with. The scope-shaped memo is harder to
disagree with because it doesn't make a specific claim.

Lesson: when authoring a phase pre-plan, follow it with a
decision-shaped memo by the next wave or two. The
scope-shaped memo identifies the surfaces; the
decision-shaped memo enables the negotiation. Worth doing
both, not one OR the other.

### 4.3 Workflow heredoc convention codification

The W15 §5.10 codifies the workflow heredoc convention as
a portable six-rule discipline. The pattern: identify a
recurring bug shape (W5-era heredoc parse error) +
generalise the fix (single-quote + env-pipe + placeholder
substitution) + write the convention into the
agent-handoff doc.

Future patterns worth identifying + codifying:
* Kubernetes ConfigMap immutability rules (do we set
  `immutable: true` on hot-reload-incompatible
  configmaps?).
* Terraform module versioning convention (when to inline
  module changes vs ship a new module version).
* Helm chart values precedence (override layering: default
  → overlay → operator).

Each candidate is a "fix a bug + write the convention"
combined wave. W15 §5.10 is the canonical shape.

### 4.4 Byte-identical kustomize-build invariants are diff-checked, not eye-balled

W15 verified the prod kustomize-build is byte-identical to
W14 via `diff .work/apone-w14-safe/prod-build.yaml
.work/apone-w15-safe/prod-build.yaml` (empty output). Same
for staging.

The W14 invariant was eye-balled (operator confirms the
commented-entry doesn't surface in the build). The W15
discipline upgrade is byte-diff. Cheap; high signal.

Worth promoting to a top-level invariant for any
overlay-side wire-up: store the W(N-1) build output in
`.work/<agent>-w<N-1>-safe/`; W(N) runs diff and surfaces
the output in the wave's commit message or PR description.
