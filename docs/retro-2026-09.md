# Monthly retro — September 2026 (Phase K, Wave 11)

> Author: Apone (DevOps)
> Period: 2026-09-01 → 2026-09-30 (W10 merged 2026-08-09 closes
> the August 2026 retro; W11 bringup runs through September).
> Cadence: monthly. September sits at the **end of Q3 2026** —
> the W8 quarterly DR rehearsal automation and the **first**
> quarterly JWT rotation under the W10 90-day cadence both
> land this month.

This retro covers Phase K Wave 11. The dominant themes are
**prod infrastructure cutover** (the W10 Redis module
re-instantiated at the prod-tier shape — `cache.r6g.large`,
multi-AZ, 7-day snapshots, CMK KMS; the prod env Terraform
stack lives alongside the existing staging + DR replica
stacks), **operator-facing hardening** (Argo Rollouts auth-
aware ingress finally lands behind the existing oauth2-proxy +
dex OIDC chain, completing the W10 deferred hand-off; CLI
Terraform pin bumped 1.9.8 → 1.10.5 with a documented quarterly
cadence), and **synthetic probe coverage expanded** (the W10
single-region prod-health-check matrix grows to 4 regions —
us-east-1, us-west-2, eu-west-1, ap-southeast-1 — with per-
region issue state and a multi-region failure-mode playbook).
Alongside, a **JWT rotation rehearsal harness** lands so the
on-call SRE can dry-run the quarterly cadence end-to-end in
staging the week before the first prod rotation at the end of
September.

The single most important takeaway is **§3.2 — rehearse before
the first quarterly rotation**. The W10 retro identified that
the first JWT rotation under the new cadence lands in late
September; W11 ships a rehearsal workflow purpose-built to
exercise the rotation flow against staging so the on-call SRE
walks into the prod rotation having muscle-memorised the
sequence. Building the harness BEFORE the first real rotation
is the W11 risk-reduction lesson — applies to every new
recurring operator drill.

## 3. Lessons learned

### 3.1 Range floor + exact CI pin is the right TF version policy

The W11 TF bump (`1.9.8` → `1.10.5`) was a single-line
workflow edit because the modules pin only a **range floor**
(`required_version = ">= 1.5.0"`) — they don't pin the CI
version. The exact pin lives only in CI workflows
(`hashicorp/setup-terraform@v3`'s `terraform_version:` input)
so the bump scope is small (one workflow file at W11), the
modules stay forward-compatible for operators running locally
on a newer CLI, and the CI lane gets deterministic plans for
plan-diff reviews. The new §6 in `docs/terraform.md`
codifies the policy + the quarterly cadence.

### 3.2 Rehearse before the first quarterly rotation

The W10 retro identified the **first JWT rotation lands at
end-Sep**. The risk: an operator running the rotation for
the first time without a dry-run hits unfamiliar SSM /
ExternalSecret / JWKS-poll edges and a flubbed sequence
invalidates every live session. W11 ships a rehearsal
workflow harness (`.github/workflows/jwt-rotation-
rehearsal.yml`) with a hard `target_env=staging` gate, the
exact rotation sequence baked in, and a 5-min JWKS-validation
loop asserting the W10 §3 invariants. The on-call SRE runs
it once against staging the week before the prod rotation —
muscle-memory before stakes.

Generalisation: every new RECURRING operator drill should
ship with a rehearsal harness BEFORE the first real
execution. Future candidates: the quarterly DR rehearsal
(W8 already automates apply/destroy, but the failover-promote
step is operator-manual — that's a rehearsal-candidate); the
RDS major-version bump (recurring annually, no rehearsal
harness today).

### 3.3 Out-of-band ESO manifests are a feature, not a smell

W11 adds TWO out-of-band ExternalSecret manifests
(`redis-connection-string-secret.yaml` for prod Redis, joining
the existing `jwt-keys-secret.yaml` for the JWT chain). Both
are intentionally NOT in any `kustomization.yaml` resources
list — they're applied manually via `kubectl apply -f` once.

This shape is sometimes flagged as a smell in code review
("why isn't it kustomized?"). The rationale is documented in
both `docs/redis-cluster.md §11.4` and the file's own header:
**these secrets bind to environment-specific KMS keys + SSM
paths that DON'T exist in dev / preview environments**, so
making them part of the kustomize tree would either break
overlay builds in those envs or require a parallel
`kustomization.yaml` per env (more files, more drift). The
out-of-band pattern is the squad's chosen trade-off — file
size is small, application is rare, drift surface is bounded
by the file's own header.

### 3.4 Multi-region probes need a multi-region failure-mode playbook

The W11 prod-health-check matrix opens the issue when ANY
single region trips the strike threshold. That's the right
default — a regional CDN outage IS a production incident
even if 3/4 regions are green. But the **action** for the
on-call SRE differs sharply between "1/4 tripped" (regional
CDN problem; check AWS Health Dashboard first) and "4/4
tripped" (global outage; check origin first). The new
`docs/edge-region-probes.md §5` ships the per-pattern
playbook so the on-call SRE doesn't waste minutes on the
wrong first-look.

Generalisation: any synthetic that fans out to N independent
probes needs a corresponding **fan-out failure-mode
playbook** — the failure-mode table is the runbook's value.

## 5. Metric movement

* **Prod synthetic probe coverage.** Pre-W11: 1 effective
  region (random US runner egress). Post-W11: 4 regions
  (us-east-1, us-west-2, eu-west-1, ap-southeast-1) — 4×
  signal fan-out.
* **Argo Rollouts dashboard access path.** Pre-W11: port-
  forward only (operator-local; not auditable). Post-W11:
  auth-aware ingress with oauth2-proxy gating (audit logs
  capture every access via the OIDC chain). Operator-local
  port-forward still works as a fallback.
* **Terraform CLI version drift.** Pre-W11: pin at 1.9.8
  (2 minors behind CLI baseline). Post-W11: pin at 1.10.5
  (current minor's stable patch); explicit quarterly bump
  cadence documented. Drift ceiling now bounded at one minor
  per quarter.
* **JWT rotation rehearsal coverage.** Net-new metric. Floor:
  0 (no rehearsal at all). Ceiling: 1 rehearsal per quarter
  (the workflow is `workflow_dispatch` only — no auto-cron).
  Q3 first rehearsal: end-Sep 2026.
