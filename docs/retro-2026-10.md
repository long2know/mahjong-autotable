# Monthly retro — October 2026 (Phase K, Wave 12)

> Author: Apone (DevOps)
> Period: 2026-10-01 → 2026-10-31 (W11 merged 2026-09-XX closes
> the September 2026 retro; W12 bringup runs through October).
> Cadence: monthly. October sits at the **start of Q4 2026** —
> the first quarter where the prod EKS cluster is genuinely a
> work-item rather than a roadmap entry; W12 ships the artifacts
> the squad needs to actually pull the cutover trigger.

This retro covers Phase K Wave 12. The dominant themes are
**prod cutover readiness** (a single-pane `docs/prod-cutover.md`
runbook supersedes the scattered "TODO: prod cutover" notes in
`docs/redis-cluster.md` and `docs/argo-rollouts-setup.md` — five
sections covering Redis terraform plan readiness, kustomization
wire-up, cutover-ready checklist, the cross-namespace kustomize
pattern, and the rollback playbook), **multi-region edge surface**
(per-region R53 ALIAS records + latency-based apex RR set + health
checks in `modules/edge/r53-regional-records.tf`, opt-in via the
new `regional_endpoints` tfvar — empty default preserves the W11
single-region apex so operators who haven't yet stood up regional
clusters see ZERO change), **operator-facing hardening continues**
(Argo Rollouts NetworkPolicy trio in the `argo-rollouts` namespace
— dashboard ingress allow-list from `ingress-nginx` + `auth`,
controller egress to kube-apiserver + Prometheus + DNS, dashboard
egress to kube-apiserver + DNS only; closes the network-level
lateral-access loop on top of the W11 identity-level loop), and
**Redis load-test re-baseline against the prod shape** (k6 manifest
at `infra/load-tests/redis-load-test.yml`, 1000 RPS sustained for
5 min, SLO thresholds wired into the k6 `thresholds:` block so a
breach fails the Job — W12 first run recorded all SLOs with > 40 %
headroom). Alongside, the **second JWT rotation rehearsal** ran
2 min 24 s (39 %) faster than the W11 first run, validating the
rehearsal harness as GA-ready and giving the squad the artifact to
promote the cadence from operator-triggered to scheduled monthly.

The single most important takeaway is **§3.2 — wire-in vs out-of-
band is a design choice, not a default**. The W11 hand-off
manifests (`redis-connection-string-secret.yaml`,
`argo-rollouts-ingress-auth.yaml`) landed with "OUT-OF-BAND" file
headers because the kustomize cross-namespace constraint wasn't
yet resolved. W12 resolved it (via `NamespaceTransformer +
unsetOnly: true`) and flipped both files to IN-BAND. The lesson:
when a hand-off ships with an "OUT-OF-BAND" qualifier, that
qualifier is a TODO — the next wave should either resolve the
underlying constraint and flip the manifest in-band, or escalate
the constraint as a permanent decision. Don't leave the hand-off
in a half-finished state across waves.

## 2. What worked well

### 2.1 Single-pane runbook

`docs/prod-cutover.md` consolidates the scattered "TODO" notes
from W10–W11 into a single chronological checklist. Two
practical wins:

* Operators no longer have to grep across five docs to find the
  current cutover status. The checklist in §3 is the single
  source of truth — items are gated by agent lane so a reviewer
  can audit completeness without cross-lane knowledge.
* Future "cutover-ready" hand-offs (e.g. DR cutover, regional
  EKS rollout) get a template they can mirror. The pattern is:
  one doc per cutover, sections 1–5 as a fixed shape (readiness
  → wire-up → checklist → design rationale → rollback).

### 2.2 `NamespaceTransformer + unsetOnly: true` pattern

The cross-namespace constraint was the chief blocker on the W11
hand-off wire-in. The W12 solution is documented in the
kustomize upstream docs (the `unsetOnly` flag is an explicit
feature, NOT a workaround) and the test surface in W12 covers
both the positive (in-base resources get `mahjong-prod`) and
negative (cross-namespace resources keep their declared ns)
cases. The pattern extends cleanly to W13+ cross-namespace
work — e.g. Prometheus AlertManager CRDs in `monitoring`,
External-DNS CRDs in `external-dns`. The W11 → W12 transition
is the canonical reference; future operators don't have to
re-discover the technique.

### 2.3 Empty-default for `regional_endpoints`

The W12 multi-region surface is opt-in via an EMPTY default on
the `regional_endpoints` tfvar. Operators who haven't yet stood
up regional clusters see ZERO terraform plan diff. The
W7 → W12 transition costs them nothing; they pick up the
multi-region path when (and only when) they're ready. This is
the inverse of the W4 → W5 RS256 transition (which required an
explicit operator action to flip the default); the W7 → W12
transition is the "frictionless additive surface" pattern that
future multi-region work should mirror.

### 2.4 Load-test as cutover gate

The W12 k6 manifest is the first cutover gate that fails CLOSED
on SLO breach (the k6 `thresholds:` block sets the Job exit
code). Pre-W12, capacity-planning artifacts were narrative
markdown ("we ran a load test and it looked good"); W12 makes
it executable. Future cutover gates (DR-replica failover, edge-
WAF rule-tightening, mobile-shell adoption) should follow the
pattern: a Job that EXITS NON-ZERO on threshold breach is
worth ten paragraphs of narrative reassurance.

## 3. What didn't work / open items

### 3.1 Stash pop tangle during W12 bringup (process lesson)

Mid-wave, an attempt to test the W11 baseline standalone via
`git stash` caused a cross-lane tangle on `git stash pop` (other
agents' work in the same session got mixed into the working
tree). Recovery required selective re-application of edits +
careful path-list staging at commit time.

**Lesson:** in a multi-agent session sharing a working tree,
NEVER use `git stash`/`git stash pop` — `stash` is a session-
level operation that other agents' work can poison. The
alternative is a per-agent worktree (`git worktree add`) when a
test needs an alternate ref, OR commit-then-revert (commit the
W12 work, check out the W11 tag, test, check out the W12
branch). The W12 retrospective captures this so W13+ doesn't
repeat the mistake.

### 3.2 Out-of-band → in-band lifecycle

W11 shipped two hand-off manifests with "OUT-OF-BAND" file
headers. The intent was clear ("operator applies these
manually"); the in-band wire-up was deferred. W12 caught up
and flipped both to in-band.

**Lesson:** when a hand-off ships with an "OUT-OF-BAND"
qualifier, the qualifier is a TODO. The next wave's planning
should either (a) resolve the constraint and flip the manifest
in-band, or (b) escalate the constraint to a permanent
decision (e.g. "this manifest stays out-of-band because [hard
reason]"). Don't carry the qualifier silently across waves —
add a planning item or it'll stay deferred forever.

### 3.3 Regional EKS clusters still pending

The W12 multi-region edge surface (R53 latency RR set + per-
region records) ships with an EMPTY default — the records
don't exist until operators populate `regional_endpoints` in
the prod tfvars. That population is blocked on the regional
EKS clusters being stood up (a Hicks W12+ item — cluster
lifecycle is not in the Apone lane).

**Open item for W13:** track the regional EKS cluster
provisioning explicitly in the Phase K W13 plan. The W12 EDGE
surface is half of the multi-region path; the W13 (or W14)
Hicks delivery completes it.

### 3.4 ClusterPolicy namespace quirk

The Kyverno ClusterPolicy in the prod overlay
(`kyverno-enforce-patch.yaml`, W4) gets `namespace: mahjong-prod`
applied by both the old `namespace:` directive AND the new W12
`NamespaceTransformer`. This is incorrect — ClusterPolicy is a
cluster-scoped resource and shouldn't have a namespace key.
The behaviour is a pre-W4 kustomize quirk, not a W12 regression
(the new transformer matches the old directive's behaviour
exactly), but the W4 design memo never caught it.

**Open item:** in W13 or beyond, add a `fieldSpecs:` exclusion
to the W12 `NamespaceTransformer` config that explicitly skips
the `ClusterPolicy` kind. This is a one-line addition to
`namespace-transformer.yaml` once the squad has bandwidth to
re-test the prod build against the change.

### 3.5 Load-test cadence not yet automated

The W12 k6 manifest is operator-triggered (one-shot Job). The
re-baseline cadence is documented (re-run on Redis engine bump,
instance-type change, etc) but the SQUAD has no automation
enforcing the cadence. A Hudson W13+ "load-test reminder"
workflow that fires every 90 days against the prod cluster
would close this gap.

## 4. Lessons learned

1. **Wire-in vs out-of-band is a design choice, not a default.**
   The "OUT-OF-BAND" qualifier on W11 hand-offs was a deferred
   TODO; W12 caught up. Track these explicitly across waves so
   they don't drift.
2. **`NamespaceTransformer + unsetOnly: true` is the cross-
   namespace kustomize pattern.** Document it in the upstream
   doc surface (`docs/prod-cutover.md §4`) so future operators
   don't re-discover it.
3. **Opt-in via EMPTY default is the right pattern for
   additive infra surface.** The W12 `regional_endpoints` tfvar
   costs operators nothing if unused; W13+ multi-region work
   should mirror the pattern.
4. **Cutover gates should be EXECUTABLE, not narrative.** The
   W12 k6 manifest is the first cutover gate that fails CLOSED
   on SLO breach. Future cutover gates should follow.
5. **Rehearsals validate runtime improvements.** The W12 JWT
   rotation rehearsal recorded a 39 % speedup downstream of
   Bishop's JWKS-cache pre-warm — the runtime change was
   measurable empirically, not theoretically. Rehearsals are
   the right artifact for capturing runtime wins; promote them
   to scheduled cadence.
6. **`git stash` is unsafe in multi-agent sessions.** Use
   `git worktree add` or commit-then-revert instead.
