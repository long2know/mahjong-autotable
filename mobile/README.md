# Mahjong Autotable — Capacitor mobile shell

Phase K Wave 2 (Apone, DevOps).

This directory ships a Capacitor 6 wrapper that bundles the existing
PWA at `../src/frontend/autotable/` into native iOS + Android apps.
The wrapper is THIN — it does not run a separate web server. It loads
the static bundle directly into a native WKWebView (iOS) / WebView
(Android), and forwards `Capacitor.isNativePlatform()` to the
frontend so it can adapt UI (e.g. hide the "Install as PWA" hint).

## What's in the box

```
mobile/
├── package.json           # Capacitor deps (kept lean; no node code lives here)
├── capacitor.config.json  # appId, webDir, native shell settings
├── README.md              # THIS FILE
├── ios/                   # gitignored — regenerated by `npx cap add ios`
└── android/               # gitignored — regenerated by `npx cap add android`
```

The `ios/` and `android/` directories are **deliberately gitignored**.
`npx cap add` regenerates them deterministically from `package.json` +
`capacitor.config.json`. Committing them only creates Xcode-project /
Gradle merge conflicts.

## Operator setup (one-time, per workstation)

### iOS

* macOS Sonoma or later.
* Xcode 15+ installed via the Mac App Store.
* CocoaPods (`gem install cocoapods` or via Homebrew).
* An Apple Developer Program enrolment (only required for distribution,
  not for `xcodebuild CODE_SIGNING_ALLOWED=NO` UNSIGNED builds).
* `XCODE_SELECT=/Applications/Xcode.app/Contents/Developer` if multiple
  Xcodes are installed.

### Android

* JDK 17 (Temurin recommended). CI uses `actions/setup-java@v4` with
  `distribution: temurin, java-version: 17`.
* Android SDK Platform 34 + build-tools 34.0.0.
* `ANDROID_HOME` env var pointing at the SDK root.
* Optional: Android Studio for IDE debugging.

## Build flow

The wrapper consumes the bundled PWA from `../src/frontend/autotable/`,
so the PWA must be built FIRST. From the repo root:

```bash
# 1. Build the web bundle (Parcel produces ../src/frontend/autotable/*).
cd src/frontend/autotable-src
npm ci
npm run build

# 2. Pull bundle into the Capacitor shell.
cd ../../../mobile
npm install

# 3. Generate native projects (one-time per workstation, or after
#    Capacitor / native deps change).
npx cap add ios       # creates mobile/ios/
npx cap add android   # creates mobile/android/

# 4. Sync the bundled web assets into both platforms.
npx cap sync

# 5a. iOS — open in Xcode (or build directly).
npx cap open ios
# OR: cd ios/App && xcodebuild -workspace App.xcworkspace \
#       -scheme App -configuration Release -sdk iphoneos \
#       CODE_SIGNING_ALLOWED=NO

# 5b. Android — open in Android Studio (or build directly).
npx cap open android
# OR: cd android && ./gradlew assembleRelease
```

## Signing identities (operator action)

Signing identities are **operator-only**; the CI workflow at
`.github/workflows/mobile-build.yml` produces UNSIGNED artefacts.

### iOS

1. Enrol in the Apple Developer Program (`developer.apple.com`).
2. In Xcode: Settings → Accounts → add Apple ID; download
   "Apple Distribution" certificate.
3. App Store Connect → Identifiers → register `io.mahjong.autotable`
   (must match `capacitor.config.json`'s `appId`).
4. Provisioning Profiles → create an "App Store" profile for the
   identifier.
5. Store the `.p12` (with empty passphrase for CI) + provisioning
   profile in 1Password under `mahjong-autotable/mobile/ios-signing/`.
6. To wire into CI later: add `secrets.IOS_DISTRIBUTION_CERT_P12` +
   `secrets.IOS_PROVISIONING_PROFILE` + `secrets.APPLE_TEAM_ID`.

### Android

1. Generate a release keystore (one-time):
   ```bash
   keytool -genkey -v -keystore mahjong-autotable-release.keystore \
     -alias mahjong-autotable -keyalg RSA -keysize 2048 -validity 10000
   ```
2. Store the keystore + the alias + keystore + key passwords in
   1Password under `mahjong-autotable/mobile/android-signing/`.
3. To wire into CI later: add `secrets.ANDROID_KEYSTORE_BASE64` +
   `secrets.ANDROID_KEY_ALIAS` + `secrets.ANDROID_KEYSTORE_PASSWORD` +
   `secrets.ANDROID_KEY_PASSWORD`.

## App-store submission (manual operator action in Phase K)

Phase K ships UNSIGNED artefacts. Distribution is manual:

* iOS: re-sign + upload to TestFlight via `xcrun altool` / Transporter.
* Android: re-sign the `.aab` via `apksigner` then upload to Play
  Console → Internal testing.

Phase L will add auto-promotion (Fastlane on iOS, bundletool +
`google-play-publisher` on Android). The CI artefact contract is
stable; only the post-build pipeline needs to grow.

## Frontend adaptation hooks (Hicks)

`@capacitor/core` exposes `Capacitor.isNativePlatform()` which the
frontend can use to:

* Hide the "Install as PWA" banner inside the native shell.
* Adapt navigation gestures for the iOS notch / Android back-button.
* Detect WebRTC permission flows via the native bridge (mic / camera).

No frontend changes are strictly required for the wrapper to ship;
the PWA works as-is. Hicks's UI passes are tracked in his queue.

## Known limitations (Phase K Wave 2)

1. **No native voice yet.** Bishop's `WebRtcVoiceHub` is on Wave 3.
   The wrapper passes the browser's `getUserMedia` permission prompt
   through — works on iOS 15+ and Android 10+.
2. **No deep links.** Universal Links (iOS) + App Links (Android) are
   a Phase L scope.
3. **No native push.** Phase L; today the PWA's `web-push` API works
   on Android only.
4. **No offline cache for game state.** Service worker caches static
   assets; persistent game state still requires connectivity (the
   reconnect flow handles this gracefully).
